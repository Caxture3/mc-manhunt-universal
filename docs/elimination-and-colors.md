# 逐人淘汰、选队颜色与刷怪笼规则

日期：2026-10-25。

## 行为

- 大厅选队立即复用正式身份的青色猎人/红色速通者显示。切换、random、退出、缩容及取消后恢复原队伍和 Tab；正式开局先移除预览，再保存正式身份的原始状态。
- capacity-cleared 仅在空闲缩容成功时触发。倒计时和运行中不清除名额，配置保存为下一局使用。
- 原先任一速通者死亡立即失败；现在为逐人淘汰，全部速通者死亡才判负。名单与身份不重分配，断线不算死亡，重复死亡不重复淘汰。
- 被淘汰者在下一 tick 按原版流程自动复活并进入旁观。复活/重连回调校验会话标识和原模式记录，避免旧任务影响新局。对局结束或管理员停止恢复淘汰前模式；离线者在重连时补做恢复。最后一名死亡直接结束本局，恢复模式规则同样适用。
- 猎人只追踪存活速通者；淘汰者不能使用指南针、提交目标选择或绑定目标末地。`/mhu status` 增加存活人数。
- 新配置 `allow-blaze-spawner-break=false`：正式 RUNNING 时保护普通烈焰人刷怪笼；空闲、倒计时及结算后不限制。true 即时允许破坏，其他普通刷怪笼和 Trial Spawner 不受此规则影响。

## 语言与数据

保留用户自定义的其余双语文本，新增配置名称与存活人数键，调整“速通者死亡”结算原因为全员淘汰。不自动改写服务器已有外部语言文件。配置文件缺少新布尔键时，沿用现有默认值补全机制。

对局和淘汰状态仍为当前服务器会话的内存状态，不增加跨服务器重启的比赛恢复协议。Fabric 和原通信格式不变。

## 验证

针对性检查覆盖大厅颜色及原状态恢复、倒计时/运行中缩容无操作、首名死亡继续/末名死亡结算/重复死亡幂等、淘汰者末地资格、自动复活旁观、断线重连、停止恢复及旧回调隔离、刷怪笼状态与开关。

实际游戏运行、多人联机、完整服务器流程未实测；编译和定点检查不视为完整游戏内验收。

`clean build` 与两个 `-PmcVersion` 独立构建均成功，每版本 34 项检查，共 68 项通过。独立只读审查未发现重要问题。发布包核对了 `/mhu` 元数据、Java 21/25 字节码、104 个双语键及占位符、九项配置描述、端侧隔离和原 Fabric 素材。
