# 选队与交互配置更新

日期：2026-10-25。

## 选队与命令

根命令从旧名称替换为 `/mhu`，无旧别名。所有玩家可执行 `/mhu join hunter|runner|random`；其余管理操作仍使用 `randomanhunt.admin`。

选队仅在没有活动会话时开放，倒计时开始即锁定本局名单和角色。初始未选队等于 random。明确选择 runner 的玩家优先占用名额，明确选择 hunter 的玩家不参与抽签；剩余名额只在 random 玩家中均匀抽取，不足时拒绝开局。仍至少保留一名猎人。

选队保存在内存中。退出服务器、正常结算、管理员停止或倒计时取消时清除；尚未创建会话的开局校验失败不清除。角色在对局中不随预约、配置或在线状态变化。

速通者名额满时拒绝新的 runner 选择，保留该玩家原选择；重复选择不改变加入顺序。离开 runner 后重新加入会排到最后。仅空闲时配置缩容成功保存后，最后加入的超额玩家恢复为 random 并收到提示；保存失败、配置非法或人数增加不会清除/恢复选择。倒计时和运行中保存 runner-count 只影响下一局，不清除选择，也不触发 capacity-cleared。

选队后 Tab/名称牌立即显示猎人青色、速通者红色。random/退出/清空恢复原来的队伍与 Tab；正式开始时先恢复预览，再由正式身份显示逻辑记录原始状态，避免结束后残留选队颜色。

## 消息交互

未开局时登录，或执行 `/mhu join`，会显示包含猎人、速通者、随机三个按钮的两行本地化消息。按钮调用公开选队命令，实际执行时仍检查会话是否已锁定。

配置行显示本地化描述和数值，整行悬停显示内部键。布尔点击读取当前值并再次检查权限，成功保存后执行原即时生效逻辑并显示新行；同一条旧消息可重复点击。数值项预填 `/mhu config <key> `，保留最后的空格。

布尔回调仅允许原接收玩家使用，有效期一小时；过期后重新执行 `/mhu config` 获取新行。控制台继续使用文本命令配置。

## 已有服务器手动更新语言文件

插件不会改写已有的 `plugins/ManhuntUniversal/lang/zh_cn.yml`、`en_us.yml`。内置文件为新默认值；外部文件仍按原规则优先覆盖，缺少的新键会回退到内置语言。

不带参数的 `/mhu` 用法提示来自 `command.usage`，在 YAML 中是 `command:` 下的 `usage:`，不在 `config.yml`。旧外部提示若仍包含 `/rmh`，占位符相同也不再覆盖新版用法，而是回退内置 `/mhu` 帮助；不会修改外部文件。该兼容检查仅用于指定用法模板，当前 `/mhu` 自定义文本继续优先。新距离刷新项的本地化键为 `config.name.tracking-distance-refresh-seconds`，非法小数提示为 `config.reason.not-decimal`。

请按需要从 JAR 或仓库中对应语言文件更新以下条目：

- `prefix`：中文为 `§8[§c穹猎追杀§8] §r`，英文为 `§8[§cManhunt Universal§8] §r`。
- `command.usage`、`game.start.usage`、`config.usage`：使用 `/mhu`，帮助包含 join。
- `game.result.full-report`：删除轮次历史标题及 `{round-history}`；`game.result.history-round-line`、`history-detail-line` 已不再使用。
- `game.start.not-enough-random`：随机候选不足时的提示，使用 `{count}`。
- `team.*`：提示、三个按钮/队伍名称、已选择、满额、锁定、清除及仅玩家可用等文本。
- `config.name.*`：九个内部配置键对应的本地化名称，包括新加入的 `allow-blaze-spawner-break`。
- `game.status.surviving-runners`：新增存活速通者计数，使用 `{alive}`、`{total}`。
- `reason.runner-died`：新版含义为所有速通者淘汰；已有自定义文本可按此更新。

`config.entry` 继续使用 `{key}` 和 `{value}`，其中 `{key}` 现在填入本地化描述；原有中文冒号分隔样式保留。旧结算模板因占位符不匹配会按现有机制回退到内置模板。

协议、Fabric 资源及网络交互未更改；旧的迁移验证文件记录当时状态，本文件描述本次更新。
