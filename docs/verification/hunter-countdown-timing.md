# 猎人等待倒计时显示时机

2026-11-07，产品1.0.0、SDK1.2.0、协议3保持不变。

原逻辑每20tick刷新ActionBar，冻结截止却按正式开局时间计算。显示刷新与整秒边界不对齐时，会先重发旧数字，近一秒后才切换，最终按原截止清除数字。因此可以出现首秒偏长、末秒偏短，不要求服务器发生明显卡顿。

修改为每tick检查剩余秒数，数字变化时立即更新；新进入等待的玩家仍立即显示。失明维护频率及统一截止、重连与重启暂停规则保持原样。没有修改Fabric、配置或语言资源。

## 针对性验证

先将原20tick显示调度独立提取，在旧逻辑下新增两项回归检查均失败，改为按剩余秒数变化刷新后通过。时间案例使用3秒等待：初次同步在0ms，首个调度回调在25ms，之后每tick为50ms。原逻辑发送 `3@0ms`、`3@975ms`、`2@1975ms`、`1@2975ms`，到3000ms截止；修改后为 `3@0ms`、`2@1025ms`、`1@2025ms`，截止仍为3000ms。另检查额外同步、跳过秒数及重置后首次刷新。

两个版本分别执行 `gradlew.bat build -PmcVersion=<版本> --offline --console=plain`，两版构建成功。Paper各338项、Fabric各12项，加上公共模块共729项检查通过。更新并核对 `dist/` 部署包和校验和，日志位于 `build/hunter-countdown-fix/`，产物报告为 `build/reports/hunter-countdown-fix-artifacts.json`。

未进行实际联机验证。刷新最多仍需等待下一次服务端tick；主线程卡顿和网络延迟无法由这一修复消除，不承诺客户端数字间隔严格等于1000毫秒。
