# 扩展 API 1.1：配置、显示与动态追踪设计

状态：原标准及新增能力方向已由用户确认；本文件为合并后的详细设计，待实施前复核。尚未修改运行时代码、API 版本或通信协议。

本设计取代原先仅覆盖配置、文本与显示的范围说明，保留其全部已确认要求，并纳入后续结构解锁、定位优化、保护和掉落功能。

## 1. 目标与方案

让服务端扩展通过稳定接口注册配置、修改规则与文本、控制显示和结算、添加或替换追踪目标，不依赖核心内部对象，不复制指南针和界面实现。

已选方案：服务端注册描述与行为，核心执行和清理；本项目 Fabric 模组解释服务器下发的目标描述。玩家只需更新本项目的模组，不需要扩展专用的 Fabric 附加模组。后续扩展添加目标不要求重新编译客户端。

考虑过但不采用的方案：

- 每个扩展附带客户端模组：可以提供任意渲染代码，但增加安装和版本匹配负担，不符合用户要求。
- 只允许 Paper Dialog 展示新增目标：实现较小，但 Fabric 界面无法统一使用新目标，不符合已确认范围。

新增目标可以使用内置背景、颜色、文字和原版物品图标。新的背景图片通过可选服务器资源包提供；资源缺失或用户拒绝资源包时使用通用背景，功能保持可用。不从插件消息下载图片，不执行服务端下发的客户端代码，不引入任意脚本或任意屏幕布局语言。

不在本次新增自定义游戏角色、核心自动轮换调度、必装协议插件或任意客户端渲染代码。API 支持创新玩法，但不内置这些玩法。

## 2. 版本、模块与兼容

- Minecraft 目标仍为 1.21.11 和 26.3；API/协议/公共逻辑使用 Java 21，两个平台版本模块分别使用 Java 21/25。
- SDK 独立版本升级为 **1.1.0**。产品版本仍为当前 **0.2.0**，除非用户另外指定发布版本。
- 通信协议升级为 **3**，与 SDK 版本独立。频道、资源/PDC 命名空间及 Mod ID 保持现有兼容标识。
- `/mhu`、权限节点、外部语言文件维护方式不变。
- 保留 API 1.0 的方法签名、已有 record 构造器和类型。新入口使用有默认实现的新增方法或新子接口，不能要求旧调用方实现新增抽象方法。
- 扩展按兼容版本范围及 capabilities 检测能力，不再使用示例中的严格 `apiVersion().equals("1.0.0")`。
- 既有 1.0 编译扩展应在新核心上链接运行；主动严格拒绝版本的第三方代码需要作者更新判断，核心无法改变其逻辑。
- `api` 仅含 Java 数据/合同；Adventure、Bukkit、Paper 事件与平台上下文放入 `api-paper`；通信 DTO 放在 `protocol`，不作为扩展 API 的数据模型。
- API 1.0 的 MATCH/ROLES/PARTICIPANTS/ELIMINATION/VICTORY 独占域继续原语义，不因新增注册默认扩大控制权限。

## 3. 统一注册、优先级与恢复

新注册继续绑定现有 ExtensionRegistration。配置、锁定、覆盖、功能策略、显示渲染器、追踪定义和提供者分别返回可关闭的子句柄。关闭幂等，插件停用自动释放，核心关停执行不可被策略阻止的清理。

文本、配置有效值及显示替换采用显式优先级；同优先级替换冲突必须明确拒绝。追加区块可组合，按优先级和扩展 ID 稳定排序。同一个功能或目标定位阶段只调用当前优先级最高的有效处理者，不能同时执行核心效果和替代效果。

注册、查询和回调原则上在主线程；不可变快照可以交给后台。保留原有重入保护。回调异常隔离并记录所属扩展；不得使主循环停止或悄悄泄露隐藏身份。

卸载一个覆盖后，应重新计算剩余覆盖和核心当前应有结果，不能恢复很早以前的过期状态。恢复显示、取消定位、关闭界面及清理对局不属于可取消的产品显示请求。

## 4. 配置注册、有效值与结构化配置

ConfigurationRegistry 支持查询、注册、保存、锁定及有效值覆盖。

- 扩展键使用命名空间，例如 `rotation:interval`；核心短名称仍可用。
- 类型包含布尔、整数、有限小数、文本、枚举、字符串列表，以及具有子项 schema 的映射/分组；可扩展解析、校验及补全。
- 描述包含本地化名称/说明、默认值、范围或枚举、单位、生效时机及读写委托。
- 扩展负责其配置持久化，核心负责统一入口、校验和操作显示；内置配置继续原子保存到现有配置文件。
- `/mhu config` 的分组格式保留逐行子项交互。例如 `runner-structure-tracker-unlock-time.village` 可单独查询、预填和修改。父分组可整体读取；API 支持整体更新，先校验完整新值再原子提交，失败不得留下部分更新。
- 父级锁定覆盖子级；子级锁定不自动锁定兄弟项。锁定仍显示接管者与原因，命令、API 和旧点击消息都重新检查权限/锁定/当前值。
- 区分保存值、当前有效值及下局值；不得把运行时覆盖写入持久化值。保存值与有效值不同时明确显示。
- 布尔点击读取最新值后切换；其他项建议预填带末尾空格的 `/mhu config <key> `。
- 配置操作有配置修订号，与对局修订号分开；需要比较并修改的 API 可拒绝过期修订。

**统一生效流程**用于保存成功、增加/撤销覆盖及扩展停用。先计算和校验候选值，提交后执行核心副作用、刷新受影响状态并发出有效值变化通知。保存失败不修改生效状态或清除预约。

现有语义不得改变：锁定角色不因人数变化重抽；仅空闲时缩容清除最后预约；强制随机与隐藏身份独立；保护/掉落优化仅 RUNNING 生效；结构解锁即时重算；距离文本刷新与定位调度分离。结构时间保留整数秒、-1 禁用；刷新间隔保留 0.1～60.0 秒及向上取 tick。

配置已提交后，观察者回调异常不能伪装成“尚未保存”；应返回已提交结果并报告异常。扩展存储委托若报告失败，则不得执行提交副作用。

## 5. 核心功能接管

配置覆盖调整参数；功能策略决定核心是否执行对应效果，二者独立。

为现有功能提供稳定、可查询的功能 ID，至少包括矿物时运、烈焰棒抢夺、猪灵交易调整、烈焰人刷怪笼保护、下界传送门保护、猎人末地限制，以及追踪发放/使用授权。结构定位的替换使用第 8 节提供者接口。

策略上下文包含功能 ID、可选对局快照、操作类型、可选玩家/角色、世界和位置等不可变数据。环境操作没有玩家时仍能判定。纯 API 不暴露 Bukkit Event。

策略可沿用核心或跳过本次核心效果。替代掉落等逻辑由接管扩展使用 Paper 事件实现，核心不重复处理；扩展也可整体暂停某项核心功能。跳过核心保护不等于撤销其他插件已作出的取消。API 不承诺凌驾于其他插件、世界权限或原版规则。

功能策略异常时沿用核心规则并记录错误；策略只改变当前操作的核心效果，不可阻止必要清理、游戏模式恢复或解除旧显示。现有最高时运/抢夺语义、单结果交易、末地永久解锁等保持默认行为。

## 6. 文本与全部服务端显示

TextRegistry 支持内置文本覆盖、扩展语言键、动态占位符以及按接收者生成内容。覆盖包含 prefix、角色显示名、配置说明、标题、提示和结算。修改显示名称不改变实际角色。

解析顺序：当前有效扩展覆盖 → 外部语言文件 → 内置语言回退。保留当前文本格式；Adventure 富文本、点击和悬停合同放在 api-paper。运行时覆盖不修改语言文件，撤销后使用当前正常解析结果。

PresentationRegistry 覆盖核心聊天、标题/副标题、Actionbar、Tab、Nametag、指南针名称/lore、Paper 菜单、声音以及打开 Fabric 选择界面的请求。每个输出包含稳定 ID、通道、接收者、相关不可变快照和敏感信息分类，可修改、整体替换、取消及刷新。

刷新明确区分文字、菜单、物品外观和定位；按玩家及通道合并。0.1 秒距离刷新不得隐式发起原版 locate、POI 搜索、结构元数据读取或昂贵扩展定位。显示回调必须快速；动态倒计时客户端按单调时钟估算，服务器以真实授权状态为准。

### 结算

提供不可变 ResultSnapshot，包含对局 ID、胜方、原因、时间、参与者最终状态及可选击杀者。支持独立 ID 区块、排序、显隐、追加及完整替换聊天/标题/声音；显示不影响判胜与清理。默认不生成轮次历史。

普通覆盖和追加遵守 hide-role-assignments；传给普通显示提供者的身份敏感上下文应按当前权限过滤。只有明确持有角色可见性控制授权的扩展才可改变该显示规则。对扩展绕过核心直接发送内容不作保护承诺。

### 逐观察者 Tab 与 Nametag

上下文为观察者和目标玩家。Tab 可设置独立文本、显隐、排序；Nametag 可设置前后缀、颜色、显隐，真实玩家名不改。核心提供两版包适配，不要求附加协议插件，不替换侧边栏。

主线程计算显示快照，网络适配不调用扩展逻辑。覆盖加入、退出、重连、角色更新、隐藏切换和扩展卸载。保留核心应有显示及恢复信息；适配失败不得将私密角色公开广播。与其他插件共存时只控制本功能负责的显示，不承诺任意其他插件发包后仍永久覆盖。

## 7. 追踪目标注册与解锁

新增 TrackingRegistry。扩展以命名空间 ID 注册目标，例如 `example:checkpoint`；内置目标在同一目录中有稳定核心 ID，不再用通信枚举充当公共接口。

定义包含名称/次级名称、本地化描述、排序、目标世界或维度策略、外观、可见/可选策略及定位提供者。自定义选择默认进入速通者结构选择界面；猎人默认追踪存活速通者的行为保持不变，本次不新增自定义角色。

外观由内置背景样式、颜色、可选原版物品图标及可选资源包纹理标识组成；纹理不存在时回退。纹理是 Minecraft 资源标识，不是 URL 或本地文件路径。普通客户端无需资源包也能选择并追踪所有可用目标。

按玩家查询可见性、锁定原因、剩余时间、当前选择及实际目标。核心内置解锁继续按正式 startedAt 计时；扩展可提供基于任务/玩家状态的可用性，不必更改整个对局时钟。角色变化、淘汰、配置更新和目标注销都重新校验。

提供目标选择变更、可用性变化和实际目标变化事件。可用性事件报告锁定/解锁/隐藏等语义变化，不因每秒剩余时间减少重复触发。解锁通知注明变化来源（自然计时、配置或扩展策略），避免扩展靠解析聊天触发逻辑。

注销目标后立即撤销选择授权、移除界面项、取消相关查询并清理选择；不自动切换到其他任意目标。内置要塞默认保留“先选结构，再找其中最近有效烈焰人刷怪笼，缺失回退”的行为。

## 8. 定位提供者、状态和异步生命周期

提供者既可实现新目标，也可按优先级替换已有目标定位。同阶段只有一个提供者执行；内置定位作为可明确选择的默认回退，扩展不得递归调用自己的替换入口。

只读快照区分目标定义 ID、搜索状态、逻辑目的地、当前指南针引导点、目标来源以及实际距离。例如跨维度时目的地仍是要塞，当前引导点是玩家所在维度的传送门；不得混为一个坐标。状态至少包括禁用/锁定、搜索中、已找到、未找到和失败。

受控操作包括选择目标、清除选择、请求重定位及特定范围失效；写操作校验注册、对局 ID、目标目录修订、当前角色/授权和可选对局修订。普通文字刷新不等于请求重定位。

提供者从主线程接收不可变请求及取消令牌，可立即返回结果或返回 CompletionStage。扩展不得在后台读取 Bukkit 世界；可在主线程采集快照后后台计算，或使用平台明确安全的异步接口。结果仅含 UUID、坐标、来源等数据，不携带世界/玩家对象。

核心统一管理有界排队、共享订阅、超时、取消及提交。默认提供者超时 10 秒，扩展定位实际在途总数最多 8，每玩家最多一个当前目标请求；这些是本次实现默认值，内置 POI/结构读取仍保留原预算，不因扩展放宽。只有提供者明确声明可共享并给出包含世界、目标、原点及策略修订的完整缓存键时才合并，不能把一个玩家的最近结果套给其他人。

超时/异常给出明确失败原因，按提供者定义选择核心回退或保持未找到；无适用默认提供者的新目标不能伪造回退坐标。取消逻辑等待不代表底层 I/O 已停止，配额直到实际完成或确认取消才释放；停用/清理后的晚到结果永不提交。

提交必须验证注册仍有效、对局、玩家当前请求、世界状态、目录/策略修订和授权均匹配。无需因为与该目标无关的显示刷新而废弃结果。世界卸载、对局结束、离线、换目标、淘汰、扩展停用均取消相关订阅。扩展刷新不得绕过核心的冷却/合并与预算。

## 9. 动态 Fabric 协议与界面

协议 3 使用目标字符串 ID 和有界描述列表替代固定三结构枚举。发送当前玩家可见的描述，不发送定位提供者代码、其他玩家私密状态或不必要的目标坐标。

打开/更新消息包含协议版本、对局 ID、授权 ID、目录修订、当前选择及目标描述；选项包含 ID、本地化主/次名称、描述、排序、外观、剩余解锁毫秒和可选状态。选择请求携带匹配授权、目录修订及目标 ID；服务器独立重验，客户端倒计时到零不代表服务端必须接受。

保留现有 ClientHello/ServerHello 引导消息的字节形状，新服务端只向协议 3 握手成功者发送动态消息。旧模组、新旧不匹配或未安装模组继续使用同一目标目录生成的 Paper Dialog。新客户端收到旧版握手否认后关闭自定义界面，不发送新选择消息。无需为了旧模组保留另一个功能残缺的动态目标协议。

默认界面每页最多三项，页内等宽，顺序为排序值后按 ID 稳定排序；超过三项分页。窗口缩小仍保持可点击区域，长文字裁切/换行而非撑出屏幕。保留现有双字号中心倒计时、锁定不提亮、允许时显示禁止鼠标标识、Esc/取消和选中态。更新移除当前页目标后修正页码，授权失效立即关闭或刷新。

实现默认边界：可注册目标总数最多 32（含内置三项），ID 最长 128 个 ASCII 字符，主/次名称各最多 64 个 Unicode 码点，描述最多 128 个码点，资源标识最多 256 个 ASCII 字符，原版物品图标仅资源 ID；不传物品 NBT。颜色为有限整数，剩余时间为 -1/0/正数约定或独立显隐状态，禁止非法长度和重复 ID。消息上限改为 64 KiB，并在读取列表/字符串前检查声明长度与总字节数；发送端也检查实际编码大小，超限返回明确错误，不部分发送目录。

64 KiB 是本协议自行收紧的目录消息上限，低于两版 Paper 的插件消息上限；客户端发往服务端的选择/关闭消息只携带短 ID 和授权，不回传整个目录。实施时分别核对收发方向的原版包限制。参考：[Paper 1.21.11 常量](https://jd.papermc.io/paper/1.21.11/constant-values.html#org.bukkit.plugin.messaging.Messenger.MAX_MESSAGE_SIZE)、[Paper 26.3 常量](https://jd.papermc.io/paper/26.3/constant-values.html#org.bukkit.plugin.messaging.Messenger.MAX_MESSAGE_SIZE)。

外观只能使用有界数据和已安装资源；不自动接受资源包。资源包被拒绝、失败、被移除或资源重载时回退内置样式。服务器资源包的制作和托管由扩展/服主负责，核心只提供纹理引用能力。

## 10. 验证与交付

保持精简验证，不要求完整游戏测试。必须包括：

- API 1.0 二进制调用样例在 1.1 实现上的链接验证；能力查询和卸载恢复。
- 配置原子保存失败、父子锁定、有效值覆盖/撤销、结构映射整体失败无部分提交、旧按钮和范围校验。
- 所有已有规则接入；接管不重复掉落，停用恢复核心，环境操作和 RUNNING 边界正确。
- 文本回退、隐藏过滤、结构化结算、显示取消不影响清理；逐观察者显示及两版适配的针对性检查。
- 新追踪目标的注册/选择/解锁/注销，已有目标替换、要塞回退和跨维度逻辑目的地/引导点区分。
- 后台只计算快照、超时、真实在途配额、共享订阅取消、目录更新及旧对局晚到结果。
