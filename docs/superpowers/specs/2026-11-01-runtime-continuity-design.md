# 猪灵蛮兵开关、跨局选队与重启续局

用户要求在正常完成 API 1.1 后实施三项改动。API 1.1 已交付验证，后续沿用产品 0.2.0、SDK 1.1.0、协议 3。

已确认：停服期间暂停计时；队伍选择只在同次服务器运行中跨对局保留，退出时清除，不跨重启保存。用户已授权继续实施，无需另设发布或提交步骤。

## 行为

1. `disable-piglin-brutes=false`。true 且 RUNNING 时拦截猪灵蛮兵生成，并清除已加载世界内现存蛮兵；实体区块载入时同样清除。空闲/倒计时不限制，修改即时生效。被移除实体不产生击杀掉落。提供 `core:piglin-brute-suppression` 功能策略，以便扩展接管，与其他 API 1.1 功能保持一致。
2. 结算、管理员停止、倒计时取消后保留显式 hunter/runner 预约与 runner 加入顺序，重新展示颜色预览；实际随机分配不写回预约。退出依旧清除，强制随机依旧立即清空，下一局开局仍遵守预约优先与候选校验。活动局期间缩容不清除；回到空闲时执行新的容量限制，通知超额玩家。
3. 保存 COUNTDOWN/RUNNING 会话并恢复原 UUID、修订、参与者/角色、淘汰、锁定设置、末地绑定、历史和计时；保存倒计时秒数及玩家重置/原失明/淘汰前模式/离线显示恢复债务。恢复 RUNNING 不再次清背包、传送或显示新开局标题。已有世界/物品状态由服务器保存，定位缓存/界面授权和原生包不序列化，重新创建。
4. 基于现有 YAML 与 AtomicFileWriter 保存有版本的 `runtime-state.yml`，不使用 Java 对象序列化或新增数据库。保存正常停服快照，并定期刷新检查点；正常停止/结算原子写入无活动局状态，防止下次复活旧局。非法/不兼容快照记录明确错误并不装载，原文件保留用于排查；不保证强制断电时世界与插件文件的跨文件事务。
5. 保存时间与恢复时间的差用于平移对局时间轴，倒计时从保存剩余秒数继续。启动后下一 tick 恢复（插件已完成注册）；离线参与者保留身份，回服应用原淘汰/待重置状态，不因全员暂时离线而判负。
6. 扩展的任意任务、provider 与内部数据不能自动持久化，仍由扩展保存/恢复；核心保留公开可读会话状态。恢复自定义追踪选择时重新验证目标注册/角色/授权，缺失或不可用则清除；不保存 API 注册句柄。

## 实现选择

唯一适合现有项目的方案是纯数据快照加现有平台恢复入口。数据库引入无必要依赖，Java 对象序列化无法保证跨版本和回调安全。快照 DTO 放 game/runtime，YAML 编解码单独放 persistence；两个服务端复用共享实现，Fabric 无协议变更。

## 验证边界

精简测试覆盖蛮兵生成/已存在/载入/开关与阶段、跨局选择/顺序/退出/容量、保存恢复的角色/淘汰/时钟/末地/待恢复债务、损坏快照/原子写入/清除旧局、重启不执行二次重置。两版单独构建和部署包/SDK/校验检查；不宣称实际游戏、崩溃恢复或其他扩展任务恢复已验证。
