# 角色调试指令

从产品版本 1.0.0 起，以下指令均使用 **`manhuntuniversal.admin`**，默认授予 OP；控制台和被授予该权限的非 OP 玩家也可使用。旧管理权限节点已移除，已有服务器需要在权限插件中手动改授新节点。选队 `join` 仍对所有玩家开放。

```text
/mhu debug
/mhu debug role-reshuffle
/mhu debug role-set <玩家> <runner|hunter>
```

`debug` 不带参数会显示用法。命令名、角色及玩家名忽略大小写，并提供上下文补全。目标来自本局固定参赛名单，可以离线；局外玩家不能作为目标。

## 随机重排

`role-reshuffle` 保持当前未淘汰速通者人数，随机重新分配可换角参与者，并保证至少一人的身份变化。离线且未淘汰的参与者可参与抽取；淘汰者、在线死亡或等待开局重置者保持原角色。

如果一次随机抽取恰好得到旧名单，会随机交换一名可换角的速通者和猎人，不无限重试。若没有可变更的身份组合则拒绝操作；该命令不是持续角色轮换，也不会启用自动轮换调度。

## 指定单人角色

`role-set` 只修改指定玩家。例如：

```text
/mhu debug role-set Alice runner
/mhu debug role-set Bob hunter
```

允许因此改变本局速通者数量，但不会修改配置中的 `runner-count` 或下一局选队预约。若指定角色已经与当前角色相同，只重放正常的身份标题/音效等展示，不更改修订、历史、指南针选择或触发角色变更事件。

## 校验与同步

两条指令只在 RUNNING 时接受，倒计时与空闲时拒绝。淘汰玩家须先通过现有复活流程显式复活，命令不会自动复活；双方仍须各有至少一名未淘汰成员。在线死亡/待重置状态继续保留原有换角保护；离线换角的重置债务会保留，重连时应用最新角色。

角色实际变化通过与扩展 API 相同的校验、提交和同步流程：更新颜色、指南针、选择授权及追踪，同时保留已知位置、原始开局时间和末地解锁。当前游戏角色会进入续局快照。不会清背包、再次传送或重新执行开局重置。

管理调试是核心操作，不需要取得或撤销某个扩展持有的 ROLES 域；正常发布 `RolesChangingEvent` / `RolesChangedEvent`，来源为 `core:debug`，reason 为对应子命令。扩展仍可取消变更，事件回调后的会话、修订和玩家就绪状态再次校验；嵌套修改返回 BUSY。原有 API `reroll` 仍允许随机结果与旧角色相同，仅 debug 的 reshuffle 保证实际变化。

隐藏角色开关继续生效：不输出具体角色的聊天名单/指令成功反馈，保留原有个人身份标题和指南针功能。普通语言及显示扩展仍可通过现有 API 覆盖这些文案或输出。

## 语言文件升级

不自动修改服务器已有外部语言文件。新增内置 `debug.*` 全部提示，`command.usage` 增加 debug；缺键时使用内置回退。如需自定义，手动从内置中英文文件合并这些条目，保留占位符。权限迁移需要修改权限插件的授权，而不是语言文件。
