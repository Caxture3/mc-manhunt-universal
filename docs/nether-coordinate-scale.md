# 下界坐标倍率

`nether-coordinate-scale` 默认 **8**，只接受 **1～2147483647** 的整数。它全程作用于所有玩家及穿门实体，包括空闲、倒计时、正式游戏、局外玩家、OP 和创造模式。

```yaml
nether-coordinate-scale: 8
```

```text
/mhu config nether-coordinate-scale 4
```

设为4时，主世界 X/Z 除以4后作为下界的出口门搜索坐标；下界返回主世界时乘以4。设为1时水平坐标一一对应。配置保存成功后，下一次穿门立即使用新值，无需重启。现有 `/mhu config` 列表支持本地化名称、内部键 Tooltip 和点击预填，管理权限为 `manhuntuniversal.admin`。

只调整主世界类型与下界类型之间的下界门事件，Y、目标世界、朝向、找门半径及建门规则不变。原版仍会寻找已有出口、在必要时创建传送门并计算最终落点，因此实际出口可能偏离理论坐标。已有门不会迁移或拆除，地图和维度数据不会被改写。默认8保留原版事件目标；非默认值按入口坐标重新投影并裁剪到目标世界边界和原版坐标极限。

玩家和实体事件均在 NORMAL 优先级处理，忽略已取消事件；后续插件仍可取消或改变目标。不处理末地、命令或其他类型的传送，也不承诺覆盖其他插件自行实现的传送系统。

结构追踪的跨维度搜索起点、移动重定位参考和扩展定位请求采用同一倍率。实际访问过的位置仍按真实坐标保留。修改生效值会取消受影响的跨维度订阅并阻止旧结果提交，随后按已有冷却和预算重新定位；有效结构缓存和已有门户 POI 预算保持不变。冷却等待期间不会继续提交旧的结构定位结果。

该配置在 API 中为 `ConfigTiming.IMMEDIATE`，支持现有配置查询、锁定、覆盖及注销恢复；修改的是全局当前值，不加入对局冻结配置，所以旧续局快照无需迁移。公开 SDK 仍为1.2.0，插件/Fabric仍为1.0.0，协议3，无需修改客户端。

内置语言新增 `config.name.nether-coordinate-scale`：中文“下界坐标对应倍率”，英文“Nether coordinate scale”。使用服务器外部语言文件时可手动补入此键；插件不会自动改写已有语言文件。
