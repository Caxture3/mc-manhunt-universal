# 开局位置与猎人等待

两项功能均仅在本局 `reset-players-at-start: true` 时执行。配置在开始倒计时（或立即开局）时冻结，后续修改仅影响下一局。

## 猎人等待

`hunter-start-wait-seconds` 默认 **0**，整数范围 **0～2147483647**。例如：

```text
/mhu config hunter-start-wait-seconds 30
```

完成开局传送和玩家重置后，全体猎人从正式开局时刻统一等待30秒。等待期间不发放追踪指南针，给予失明，锁定实际传送落点；允许转动视角、聊天和查看背包，禁止移动/传送、攻击、方块/实体/物品交互、拾取/丢弃、背包编辑、切换副手及骑乘，并免受伤害。个人 ActionBar 显示 `开始行动：{seconds}`，剩余秒数向上取整。原版实体伤害以外的载具/悬挂实体攻击入口也受到限制。

结束等待后清除本功能持有的限制及失明，按当前指南针配置和扩展功能接管规则补发指南针。未打开猎人指南针时不会强行发放。等待期内切换角色不会重置计时或重置玩家：新速通者立即解除等待，新猎人仅等待原截止时刻前的剩余时间；淘汰者不继续等待。停止、结算及停服清理也解除限制。

断线不暂停本局统一计时，重连时只等待剩余时间。正常停服暂停计时，续局继续剩余等待；不会再次重置或传送已完成重置的玩家。已保存的等待锚点用于恢复冻结，离线待重置玩家则先完成原分配位置的补偿重置。

## 玩家开局位置

默认两队均使用服务器第一个世界的出生点，保持原行为：

```yaml
player-start-pos:
  hunter:
    mode: world-spawn
    custom: []
  runner:
    mode: world-spawn
    custom: []
```

每队独立选择模式，切换模式不会删除自定义列表：

| 模式 | 含义 |
| --- | --- |
| `world-spawn` | 服务器主世界出生点 |
| `player-spawn` | 玩家有效床/重生锚位置，保留对应世界；没有有效个人重生点时回退主世界出生点 |
| `custom` | 按对应队伍列表依次分配 |

```text
/mhu config player-start-pos.hunter custom
/mhu config player-start-pos.runner player-spawn
/mhu config player-start-pos.hunter.add-custom 535 15 235
/mhu config player-start-pos.hunter.remove-custom 535 15 235
```

坐标接受有限的绝对小数，不支持 `~`。添加时保存执行玩家所在世界的 UUID/名称；控制台使用主世界。移除命令匹配执行者对应世界和 XYZ；聊天按钮则精确匹配该条记录，不要求执行者身处记录所在世界。同一世界内重复的完全相同 XYZ 被拒绝，世界名称变化不影响 UUID 匹配。

`/mhu config` 和位置查询展示两队可点击的模式、绿色选中标记、自定义坐标及移除按钮；悬停坐标显示世界信息。`[+ 添加新位置 +]` 预填相应的 `/mhu config player-start-pos.hunter.add-custom ` 或 `runner.add-custom `，保留末尾空格。模式和移除操作会重新检查管理权限及配置锁；过期移除按钮不会误删新记录，而是提示并刷新列表。

开局按固定参与者 UUID 顺序在各队内分配位置，第 N 名使用 `(N-1) % 位置数量` 对应项；人数多时循环，人数少时忽略剩余位置，不随机。进入倒计时时固定每人的实际目标；期间离线也保留其名额和目标，后续补偿重置使用同一目标。

任一队选中 `custom` 却没有位置时，在创建对局和重置玩家前拒绝开局。已分配目标所在世界须已加载，坐标和高度须合法；自定义位置按原坐标传送，不会自动寻找地面或避开方块。批量传送继续沿用原有先全部传送成功、再执行玩家重置的流程。个人出生点和世界出生点同样在本局准备时解析，后续改床或改世界出生点不会改写已经锁定的目标。

## 扩展与兼容

公开 API 配置注册中两项均为 `NEXT_MATCH`，使用已有锁定、覆盖和原子保存入口。`player-start-pos` 是完整映射根，角色下含 `mode` 和 `custom` 叶项；自定义条目为包含 `world`（UUID字符串）、`world-name`、`x/y/z` 的映射。无新 Fabric 协议或附加客户端模组，产品1.0.0、SDK1.2.0、协议3保持不变。

续局快照新增冻结的开局设置、每人目标及等待锚点。旧快照按等待0秒、原有世界出生点规则补齐新冻结键；只有缺少整组新数据的旧格式会获得这些默认值，缺失部分新字段仍作为非法快照处理并保留文件。原角色、淘汰、重置债务及离线暂停时轴继续沿用。

新内置文本位于 `config.description.hunter-start-wait-seconds`、`config.description.player-start-pos.title`、`start-pos.*` 和 `hunter-start.countdown`。已有外部语言文件不自动改写，可对照仓库双语资源手动补入。
